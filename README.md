# 운영 매뉴얼 — 프로세스와 사용법

이 아래는 **개발자가 아니라 실제 업무를 처리하는 관리자·라이더를 위한 사용 설명**입니다. 코드/배포 관련 내용은 위 섹션과 [LOGIC.md](LOGIC.md)를 참고하세요.

## 1. 조직 구조 이해

이 시스템은 **본사 → 총판 → 대리점** 3계층 구조입니다.

- **본사**: 전체 데이터 조회·설정 가능(스코프 제한 없음)
- **총판**: 소속 대리점들의 데이터만 조회·관리
- **대리점**: 자기 대리점 소속 라이더 데이터만 조회·관리

관리자 계정은 하나의 조직(본사/총판/대리점 중 하나)에 소속되며, **모든 목록·조회 화면은 로그인한 계정의 소속 범위 안에서만 데이터를 보여줍니다.** 예를 들어 대리점 담당자로 로그인하면 다른 대리점의 라이더·정산·출금 데이터는 아예 보이지 않습니다.

## 2. 전체 업무 흐름 (한눈에 보기)

```
① 라이더 등록                (라이더 관리 → 신규 등록, 또는 정산 업로드 중 자동 등록)
        ↓
② 정산 엑셀 업로드            (정산 업로드 → 엑셀 업로드)
        ↓  (미리보기 단계에서 매칭 확인)
③ 미매칭 라이더 처리          (그 자리에서 연결/등록, 또는 업로드 이력에서 사후 처리)
        ↓
④ 확정 저장                  (업로드 확정 → settlement_daily_riders에 저장)
        ↓
⑤ 정산 반영                  (업로드 상세 → "정산 반영 · 수수료·지갑" 버튼)
        ↓  (원천세·보험료·수수료·미수금 등 자동 차감, 라이더 지갑에 적립)
⑥ 라이더 확인                (라이더 앱 → 정산 달력/수수료 내역에서 확인)
        ↓
⑦ 출금 신청                  (라이더 앱에서 기간 선택 후 신청)
        ↓
⑧ 관리자 처리                (출금 목록 → 이체파일 다운로드 → 은행 이체 → 처리 완료 클릭)

※ 프로모션은 위 정산 흐름과 별개 (프로모션 지급 → 템플릿 다운 → 금액 입력 → 업로드 → 확정, §5-1)
```

이 흐름에서 **"정산 반영"이 핵심 분기점**입니다. 업로드만 하면 원본 데이터가 저장될 뿐 라이더 화면에는 아무것도 안 보이고, 지갑에도 적립되지 않습니다. 반드시 업로드 상세 화면에서 "정산 반영" 버튼을 눌러야 라이더가 결과를 볼 수 있고 출금도 가능해집니다.

## 2-1. 용어 정리 (수수료·차감 4종)

화면 곳곳에서 쓰는 이름이 정해져 있습니다. 서로 성격이 다르니 구분해서 보세요.

| 이름 | 무엇 | 언제 발생 | 얼마 |
|------|------|-----------|------|
| **정산수수료** | 라이더가 출금할 때 주문 **건별**로 붙는 금액 | 출금 신청 시점 | 정산일로부터 기준일(기본 7일) 이내 주문은 비싼 단가, 지난 주문은 싼 단가 (대리점별 설정) |
| **플랫폼 수수료** | PG 카드결제에 붙는 **비율**을 본사·총판·대리점이 나눠 갖는 몫 | PG 결제 시점 | 대리점마다 본사/총판/대리점 %를 따로 설정 |
| **보험료** | 고용보험 · 산재보험 · 시간제보험 | 정산 반영 시점 | 요율 또는 정산서 값 |
| **미수금** | 대여금 · 리스/렌탈 · 선지급 — **수수료가 아니라 원금 상환 차감** | 정산 반영 시점 | 등록된 잔액·일납 기준 |

## 3. 정산 업로드 — 상세 절차

**메뉴: 정산 업로드 → 엑셀 업로드**

1. 배달 플랫폼(쿠팡이츠/배달의민족)에서 받은 정산 엑셀 파일을 업로드합니다. 파일명에 날짜가 포함돼 있으면 정산일이 자동으로 채워지고, 플랫폼도 파일 내용을 보고 자동 감지됩니다(감지 결과와 다른 플랫폼을 선택하면 경고가 뜹니다).
   - **팀명·지역명**도 파일명(`팀_지역_날짜.xlsx`)에서 자동으로 채워집니다. 형식이 다르면 직접 입력하세요.
   - **같은 대리점이라도 팀지역이 다르면 같은 날짜에 여러 건을 올릴 수 있습니다.** 팀지역이 같은 자료를 또 올리면 중복으로 막힙니다. 라이더 한 명이 같은 날 두 팀지역에서 일했다면 정산 내역도 팀지역별로 각각 쌓입니다.
2. **미리보기**가 뜹니다 — 실제 저장 전에 몇 명이 매칭됐고 몇 명이 안 됐는지 보여줍니다.
   - **매칭됨**: 초록 배지로 라이더 이름·코드가 표시됩니다.
   - **미매칭**: "미매칭 · 연결/등록" 버튼이 뜹니다. 클릭하면:
     - **신규 라이더 등록**: 이름만 입력하면 등록됩니다(로그인 ID는 비워두면 휴대전화번호 기반 자동 생성, 비밀번호는 `0000` 고정).
     - **기존 라이더에 연결**: 이름/코드로 검색해서 찾은 다음 "연결" 클릭 — 오타나 개명으로 이름이 달라 매칭이 안 됐을 때 씁니다. 검색은 정확히 일치하지 않아도 비슷한 이름 순으로 후보를 보여줍니다.
3. 미매칭을 다 처리했으면(또는 나중에 처리하기로 하고) **"확정 업로드"** 버튼을 누릅니다. 이 시점에 원본 데이터가 DB에 저장됩니다.

### 확정 저장 후 미매칭이 남아있다면

**메뉴: 정산 업로드 → 업로드 이력 → 해당 업로드 클릭**

- 라이더 목록에서 "미매칭" 필터로 걸러볼 수 있고, 각 행마다 "연결/등록" 버튼으로 그 자리에서 바로 처리 가능합니다(미리보기 때와 같은 방식). 연결하는 즉시 같은 업로드의 다른 원본 데이터(오더상세·시간제보험·지원금·차감내역)까지 자동으로 같이 매칭됩니다.
- **이미 매칭됐지만 잘못 매칭된 경우**(동명이인 등)도 "재연결" 버튼으로 교정할 수 있습니다. 단, **이미 "정산 반영"까지 끝나 지갑에 적립된 건은 자동으로 되돌리지 않고 막힙니다** — 이 경우는 라이더 상세 화면의 미수금/수동조정 등으로 직접 정리해야 합니다.

### 정산 반영

같은 업로드 상세 화면 상단의 **"정산 반영 · 수수료·지갑"** 버튼을 누르면:
- 매칭된 라이더들에 대해 원천세(대상자만)·보험료(고용·산재)·선정산수수료(대행)·미수금 차감을 계산해서 확정하고, 실지급액을 라이더 지갑에 적립합니다.
- **이미 반영된 날짜·라이더·플랫폼 조합은 자동으로 건너뜁니다** — 같은 업로드에 버튼을 다시 눌러도 안전합니다(중복 적립 없음). 그래서 미매칭 건을 나중에 연결한 다음 다시 눌러도(이때는 버튼 문구가 "정산 재반영(신규 매칭분)"으로 바뀝니다) 새로 매칭된 건만 추가로 반영됩니다.

## 4. 정산 수수료·차감 조회

- **메뉴: 정산 업로드 → 정산 수수료 내역** — 정산 반영이 끝난 사이클을 라이더·정산일별로 조회. 각 행의 "내역" 버튼으로 그 사이클의 수수료 항목(원천세·보험료 등) 상세를 봅니다.
  - **기간 조회**: 정산일 from/to를 직접 입력하거나, 아래 **기간 바로가기** 버튼(오늘 / 최근 7일 / 이번 달 / 지난 달 / 최근 90일)으로 한 번에 선택합니다. 현재 조회 중인 기간과 일치하는 버튼은 파란색으로 표시됩니다.
  - **기간 합계**: 상단 카드에 조회 기간의 플랫폼 지급 합계(지원금 포함)·수수료 합계·지갑 반영 합계가 나오고, 목록 맨 아래에도 합계 행이 있습니다.
  - **상세 내역 합계(항목별)**: 그 기간에 발생한 차감을 종류별(원천세 / 고용보험 / 산재보험 / 시간제 보험 / 선정산수수료 등)로 건수·금액·비중까지 집계해 보여줍니다. 미수금(대여금·리스·선지급)은 수수료가 아니라 원금 상환이라 "차감(원금상환)" 배지가 붙고 수수료 합계에서는 빠집니다.
  - ⚠️ 목록이 많으면 화면에는 일부만 표시되지만, **합계는 항상 조회 기간 전체 기준**입니다(화면에 보이는 행만 더한 값이 아님).
- **메뉴: 정산 업로드 → 수수료·차감 통합** — 위 화면과 달리 **출금 시점 수수료**(정산수수료, 출금 신청할 때 발생)까지 같이 봅니다. 라이더별로 "출금 수수료 / 대행수수료 / 원천세 / 보험료 / 수수료 합계 / 미수금 차감"을 한눈에 집계해서 보여주고, "내역" 버튼으로 건별 시계열(언제·어느 시점에·얼마)을 봅니다. **미수금은 수수료가 아니라 원금 상환 차감이라 별도 열로 분리**돼 있습니다.
- **메뉴: 정산 업로드 → 원천세 명세** — 원천세 대상자로 지정된 라이더만 모아서 원천세 누적액을 봅니다.

두 목록 화면 모두 **페이지당 30건씩 나뉘어 표시**되고, 페이지 번호 클릭·페이지당 건수 변경(20/30/50/100)이 새로고침 없이 즉시 반영됩니다.

## 5. 미수금(대여금·리스·선지급) 관리

**메뉴: 선공제(대행) → 미수금 원장**, 또는 라이더 상세 화면에서도 등록/조회 가능.

- **대여금(loan)·선지급(advance)**: 원금이 있고 차감할 때마다 잔액이 줄어듭니다. "차감" 버튼으로 금액을 입력해 상환 처리합니다.
- **리스/렌탈(lease)**: 원금 개념이 없고 일납(하루 요금) × 경과일수만큼 반복 부과됩니다. 계약 시작일(`opened_on`)과 종료 예정일(`planned_end_on`)을 등록해두면, 정산 반영 시 계약기간과 정산기간이 겹치는 일수만큼 **자동으로 계산해서 차감**됩니다(수동 입력 불필요). 같은 정산을 재반영해도 이중 차감되지 않습니다.
- 차감 이력은 각 건 아래 "이력" 버튼으로 펼쳐볼 수 있고, 잘못 눌렀으면 "취소"로 되돌릴 수 있습니다(단, 정산 반영에 이미 반영된 후라면 신중하게 처리).

라이더 앱에서도 본인 미수금 잔액과 차감 이력을 조회할 수 있습니다(내 정보 → 대여금·리스, 읽기 전용).

## 5-1. 프로모션 지급

**메뉴: 프로모션 지급**

정산과 별개로 대리점이 라이더에게 주는 돈입니다. 프로모션1·프로모션2 두 가지를 한 번에 지급할 수 있습니다.

**절차**
1. **템플릿 다운로드** — 대리점을 고르고 버튼을 누르면 그 대리점 활동 라이더가 **미리 채워진** 엑셀이 받아집니다.
   - 컬럼: `라이더코드` / `라이더이름` / `프로모션1` / `프로모션2`
   - 라이더코드·이름은 **그대로 두고**, 프로모션1·2 금액만 채우세요. 줄 사람만 채우면 됩니다(0원이거나 빈칸이면 지급 대상에서 빠집니다).
   - 금액은 `20000`이든 `20,000`이든 상관없습니다.
2. **지급 일자 선택** — 이 날짜로 지급 처리됩니다.
3. **파일 업로드 → 미리보기** — 몇 명에게 얼마가 나가는지, 매칭 안 된 줄은 없는지 확인합니다.
   - 같은 지급일자에 **이미 프로모션을 받은 라이더**가 있으면 경고가 뜹니다. 그대로 진행하면 **추가로 더** 지급됩니다.
4. **지급 확정** — 라이더 한 명씩 **카드로 결제**한 뒤(프로모션 금액 + 플랫폼 수수료), 결제가 성공한 건만 라이더 지갑에 적립됩니다.

**결제가 실패하면**
- 등록된 카드를 우선순위대로 시도하고, 한도초과 등으로 실패하면 다음 카드로 자동 재시도합니다.
- 모든 카드가 실패한 라이더는 **지급되지 않고** 사유가 기록됩니다. 일부만 실패해도 나머지는 정상 지급됩니다.
- 카드 한도를 늘리거나 카드를 추가한 뒤, **지급 상세 화면의 "재시도"** 버튼으로 실패 건만 다시 결제할 수 있습니다. 이미 지급된 사람에게 중복으로 나가지 않습니다.

라이더는 앱의 **프로모션** 메뉴에서 받은 내역(프로모션1/2 구분, 날짜별)을 확인합니다.

## 6. 출금 처리 절차

### 라이더가 신청

라이더 앱 → 출금 신청 화면에서 **달력에 미출금 정산일이 금액과 함께 표시**됩니다. 날짜를 클릭하면 "가장 오래된 정산분부터 그 날짜까지" 출금 범위가 정해지고(임의 날짜 여러 개를 따로 고르는 방식이 아님 — 정산수수료가 경과일수 기준 요율이라 오래된 것부터 순서대로 나가야 정확합니다), 화면에 실지급 예정액이 즉시 다시 계산돼 표시됩니다. "출금 신청" 버튼을 누르면 신청이 접수됩니다.

- 신청 즉시 보증금(기본 5만원, 항상 지갑에 남겨둠)을 제외한 금액에서 정산수수료(주문 건별 경과일 요율 — 7일 이내 80원/이후 40원, 대리점별로 다를 수 있음)를 뺀 금액이 실지급 예정액입니다.
- 이미 처리 중인 신청이 있으면 새로 신청할 수 없습니다(완료 후 재신청).

### 관리자가 처리

**메뉴: 출금 → 출금 신청 목록**

1. 대기 중인 신청들을 확인하고 **다운로드** 메뉴에서 은행 이체파일(신한 BizBank 양식)을 받습니다.
2. 실제로 은행에서 이체를 실행합니다.
3. **처리 완료** 메뉴에서 완료 처리하면 상태가 "처리 완료"로 바뀌고 라이더 지갑에서 최종 차감됩니다.
4. 신청을 반려하면 점유했던 정산 사이클이 다시 미출금 상태로 풀립니다(다시 출금 신청 가능).

라이더는 출금 신청 내역에서 각 건을 클릭하면 **정산조회 상세** 화면으로 들어가 실수령금액/정산 총액/공제 내역(정산 반영 시점 공제 + 출금 시점 공제로 구분)과 일별 상세를 볼 수 있습니다.

## 7. 라이더 관리

**메뉴: 라이더 → 라이더 관리**

- 신규 등록, 상세 정보 수정, 상태 변경(활동중/일시정지/탈퇴요청/계약종료)
- **비밀번호 정책**: 신규 등록·초기화 시 비밀번호는 항상 **`0000`**으로 통일됩니다. 라이더가 `0000`으로 로그인하면 **비밀번호 변경 화면이 강제로 뜨고, 직접 새 비밀번호를 정하기 전까지 앱의 다른 화면을 쓸 수 없습니다.** 관리자가 임의 비밀번호를 만들어 전달할 필요가 없습니다(라이더 상세 → "비밀번호 초기화" 버튼).
- 로그인 ID는 휴대전화번호가 있으면 그 번호로, 없으면 임의 코드로 자동 생성됩니다(휴대전화번호 중복 시 알파벳 접미사 추가).
- **플랫폼 ID 연동(쿠팡/배민 매칭 키)**: 팀지역마다 쿠팡 ID가 다를 수 있어 **한 라이더가 여러 개를 가질 수 있습니다.** 목록에서 개별 삭제하거나 아래 입력란으로 추가하세요. 정산 업로드 시 등록된 ID 중 **어느 것으로든** 매칭됩니다. 단, 같은 대리점 안에서 다른 라이더가 쓰는 ID는 등록할 수 없습니다.
- 미수금(대여금/리스/선지급) 등록도 이 화면에서 합니다.

## 8. 조직·시스템 관리 (본사 전용 메뉴 다수)

- **조직 관리(총판·대리점)**: 총판·대리점 신규 등록, 계층 구조 관리
- **수수료 설정**: 대리점마다 두 가지 수수료를 각각 설정합니다(§2-1 용어 참고).
  - **정산수수료** — 경과일 기준(기본 7일), 기준 이내/경과 건당 단가, 보증금
  - **플랫폼 수수료** — 본사 몫 / 총판 몫 / 대리점 몫 %를 각각 입력하면 합계가 즉시 표시됩니다. **대리점마다 본사·총판 몫까지 다르게 줄 수 있습니다.**
- **관리자 계정·권한**: 관리자 계정 발급, 소속 조직·역할(super/manager/operation/settlement/admin) 지정
  - **총괄 관리자**(`manager`, 2026-08-05 신규): 대리점·총판 담당자 한 명이 그 조직의 업무 전체(정산·차감·수수료/미수금·프로모션·출금·콘텐츠·라이더)를 혼자 처리해야 할 때 쓰는 역할입니다. 아래 「권한 관리」 설정과 무관하게 **소속 조직 범위 안에서는 항상 전체 화면을 조회·수정**할 수 있습니다. 다만 **시스템 관리는 총괄 관리자도 접근할 수 없고 최고 관리자만 가능**합니다. 총판·대리점의 대표계정도 자기 조직 서브계정에 이 역할을 부여할 수 있습니다(대표·서브계정 화면).
- **권한 관리** (2026-08-05 신규): 운영/정산/조회 역할별로 화면(정산 업로드·차감·수수료/미수금·프로모션·출금·콘텐츠·라이더)의 **조회/쓰기 권한을 체크박스로 직접 설정**합니다(최고 관리자·총괄 관리자는 항상 전권이라 이 표에 없습니다). 조회 권한이 없으면 그 메뉴는 사이드바에서 아예 사라집니다(쓰기 체크 시 조회는 자동으로 함께 켜집니다). **시스템 관리(이 §8 전체)는 이 화면과 무관하게 항상 최고 관리자 전용으로 고정**되어 있어 설정으로 바꿀 수 없습니다 — 나중에 메뉴가 늘어나도 시스템 관리는 손댈 필요 없이 그대로 최고 관리자만 접근합니다.
- **코드/마스터**: 은행 코드, 차량 유형 등 시스템 공통 코드 관리 — 여기서 은행을 추가/변경하면 라이더 앱 계좌 정보 화면에도 자동 반영됩니다.
- **감사 로그**: 누가 언제 무엇을 바꿨는지(수동조정, 라이더 매칭 교정 등) 기록 조회
- **정산/잔액 수동 조정**: 특수한 상황(오류 정정 등)에서 지갑 잔액을 직접 조정. 신중하게 사용하고 사유를 반드시 남길 것.

## 10. 자주 겪는 상황과 대처법

- **"미매칭 N명"이 계속 남아있다**: §3의 "확정 저장 후 미매칭이 남아있다면"을 따라 업로드 상세에서 연결/등록 처리 후, "정산 재반영" 버튼을 눌러 반영하세요.
- **라이더가 정산 화면에 아무것도 안 보인다고 한다**: 업로드만 하고 "정산 반영"을 안 눌렀을 가능성이 가장 큽니다. 해당 업로드 상세에서 상태가 "반영완료"인지 확인하세요.
- **정산서 이름과 등록된 라이더 이름이 달라서 매칭이 안 된다**: 연결/등록 모달의 "기존 라이더에 연결" 탭에서 이름 일부만 입력해도 비슷한 이름 순으로 후보가 뜹니다.
- **엉뚱한 라이더에게 매칭된 것 같다**: 업로드 상세에서 그 행의 "재연결" 버튼으로 교정하세요. 단 이미 지갑에 적립된 건은 자동 교정이 막히니 수동조정으로 처리해야 합니다.
- **대리점 계정으로 다른 대리점 데이터가 안 보이는 게 정상인지**: 정상입니다(§1 참고). 본사·총판 계정만 하위 조직 데이터를 함께 봅니다.
