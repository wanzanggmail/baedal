# 현재 제약 및 주의사항

이 문서는 현재 구현을 운영에서 오해하지 않도록 목업, Mock 연동, 문서와 코드의 차이, 확인이 필요한 정책을 정리합니다.

## 1. 운영 판단에 사용하면 안 되는 화면

### 라이더 정산 목록

- 경로: `settlement/list`
- 상태: 하드코딩 목업
- 주의: 요기요를 포함한 예시 데이터가 표시될 수 있음
- 실제 확인: `정산 수수료 내역`, `정산 달력`

### 라이더 정산 상세(샘플)

- 경로: `settlement/detail`
- 상태: 정적 샘플
- 실제 확인: 정산 수수료 상세 또는 출금 상세

목업 화면의 금액, 플랫폼, 상태를 지급·민원·회계 자료로 사용하지 않습니다.

## 2. 외부 금융 연동

### PG

`PgGateway`는 현재 Mock입니다. 프로모션 지급과 대리점 수동 충전에서 결제 성공 기록이 생성되어도 실제 카드 승인과 동일하지 않습니다.

### 오픈뱅킹

`OpenBankingGateway`와 `Disbursement`의 이체도 Mock입니다. 일일정산 지급과 대리점 인출의 완료 상태를 실제 은행 이체로 간주하지 않습니다.

### 신한 이체파일

주정산 출금은 신한 BizBank용 xlsx/txt/csv 다운로드 방식이 실제 화면에 남아 있습니다.

```text
파일 다운로드
≠ 실제 이체 완료
```

은행 시스템의 성공 결과를 확인한 뒤 관리자 화면에서 완료 처리해야 합니다.

## 3. 정산 반영과 PG 충전

설계 문서 일부에는 정산 반영이 PG 결제를 자동 실행하는 것으로 설명되어 있으나 현재 정산 반영 API는 `PgPayment::fundAppliedUpload()`를 호출하지 않습니다.

- 정산 반영: 라이더 정산 사이클과 지갑 적립
- PG 충전: 프로모션 지급 또는 결제 설정의 별도 흐름
- 영향: 선정산 지급 전에 대리점 지갑 잔액을 별도로 확인해야 함

## 4. 선정산 라이더의 앱 출금

업무 정책상 선정산 라이더는 대리점의 **일일정산 지급**으로 처리합니다. 그러나 현재 `Withdrawal::applyForRider()`는 선정산 라이더의 앱 출금을 코드로 차단하지 않습니다.

운영 기준:

1. 선정산 여부를 라이더 상세에서 확인합니다.
2. 선정산 라이더에게 앱 출금 신청을 안내하지 않습니다.
3. 신청이 들어오면 중복 지급 가능성을 확인한 뒤 처리 또는 반려합니다.

## 5. 라이더 계좌 UX

라이더 홈과 출금 화면에서 계좌 등록을 유도할 수 있지만 `profile/bank`는 읽기 전용입니다.

- 등록·변경: 대리점 관리자
- 라이더 앱: 등록 정보 확인만 가능
- 민원 안내: 계좌번호를 메신저로 받기보다 승인된 안전한 절차 사용

## 6. 로그인 팝업 공지

로그인 시 팝업 공지 큐를 세션에 저장하는 로직은 있으나 이를 화면에 표시하는 렌더링 코드는 확인되지 않습니다. 일반 공지 목록은 정상적인 조회 경로입니다.

## 7. 메뉴와 접근 경로

### 출금 정책

`withdrawal/settings`는 구현되어 있지만 사이드바에 독립 메뉴가 없습니다. 대리점 계정이 출금 신청 목록의 설정 버튼으로 진입합니다.

### 선지급 입력

`deduction/advance` route와 API는 남아 있지만 사이드바 메뉴는 제거되었습니다. 운영에서는 **미수금 원장**의 선지급 유형을 사용합니다.

### 대표·서브계정

총판·대리점의 대표계정만 사용할 수 있습니다. 대표계정은 조직 내 최초 관리자 ID를 기준으로 판별하므로 계정 삭제·이관 시 주의합니다.

## 8. 권한 관련 주의

- `super`: 역할 권한표와 무관하게 전권
- `manager`: 일반 업무 전권이지만 `system/*`는 제한
- `system/*`: 대부분 최고 관리자 전용
- 조직 관리: 본사 레벨 최고 관리자 전용
- 공지·배너 작성: 본사 조직 추가 조건
- 프로모션 화면은 promotion 영역이지만 일부 지급 API는 settlement 쓰기 권한을 검사
- 기본 시드에서 settlement 역할은 출금 쓰기 권한이 없음

버튼 노출과 API 저장 권한이 완전히 같지 않은 화면이 있으므로 권한 테스트는 실제 저장 요청까지 확인해야 합니다.

## 9. 수수료 정책 확인 사항

다음 값은 실 운영 계약과 비교가 필요합니다.

- 최근/장기 정산의 건당 출금수수료
- 보증금 금액
- 선정산 대행 수수료 구간
- 플랫폼 수수료 본사·총판·대리점 분배율
- 고용보험·산재보험 비율

코드의 기본값이나 시드값을 계약 확정값으로 간주하지 않습니다.

## 10. 출금 정책 설명의 혼재

일부 화면·문서는 구 `accrued_days` 단일 구간 설명을 사용하고, 현재 출금 계산은 `WithdrawalCycles`와 경과 기간별 건당 수수료를 사용합니다.

운영 검증은 실제 출금 미리보기 결과와 다음 항목을 기준으로 합니다.

- 선택된 정산 사이클
- 주문 건수
- 정산일 경과 기간
- 대리점별 보증금과 단기·장기 수수료

## 11. DB·시드 차이

### 차감 기본값

`seed.php`의 일부 차감 기본값과 `MigrateRunner`의 최신 분리값이 다를 수 있습니다. 신규 설치는 반드시 `migrate.php` 후 `seed.php` 순서로 실행하고 실제 DB 값을 확인합니다.

### 레거시 seed.sql

`seed.sql`은 최신 조직·멀티테넌시 구조를 모두 반영하지 않습니다. 신규 설치에서는 `seed.php`를 사용합니다.

### 상태값

상태는 DB enum, PHP 라벨, `system_codes`에 중복 정의될 수 있습니다. 새 상태를 추가할 때 세 위치와 매뉴얼을 함께 갱신합니다.

## 12. 배포 제약

- GitHub Actions는 DB 마이그레이션을 자동 실행하지 않음
- `migrate.php`, `seed.php`, `vendor/`는 rsync 제외
- 스키마 변경과 Composer 변경은 서버에서 별도 처리
- `--delete`로 Git에서 삭제된 일반 파일은 서버에서도 삭제
- `.env`, uploads, storage는 배포로 갱신되지 않음

코드 배포 성공만으로 운영 반영이 끝난 것으로 판단하지 않습니다.

## 13. 백업·모니터링 제약

- 저장소 내 자동 DB 백업 없음
- cron 또는 작업 스케줄러 없음
- 전용 HTTP health endpoint 없음
- `db_ping()`은 존재하지만 모니터링에 연결되지 않음
- 정산 반영, 프로모션 지급, 일일정산 지급은 관리자 수동 실행

운영 인프라에서 DB 백업, 서비스 헬스체크, 로그 알림을 별도로 구성해야 합니다.

## 14. 보안 위험

- `.env`가 없을 때 `inc/db.php`의 기본 DB 값으로 접속을 시도할 수 있음
- `.env.example` 값은 운영에 재사용하지 않아야 함
- `seed.php`는 웹 접근이 가능할 수 있으므로 운영에서 차단 필요
- Mock 금융 결과가 실제 처리처럼 화면에 보일 수 있음
- FK가 없는 일부 조직 참조는 앱 로직으로 정합성을 보장함

## 15. 한글 팀/지역 중복

팀명과 지역명은 유니코드 NFC 정규화를 사용합니다. 외부 파일의 조합형/완성형 혼재로 중복 키가 우회되지 않도록 업로드 후 팀/지역 표기를 확인합니다.

## 16. 정정 작업

정산 반영 뒤 원본 업로드를 직접 삭제하거나 플랫폼 값을 단순 변경하면 다음 데이터가 어긋날 수 있습니다.

- 라이더 매칭
- 정산 사이클
- 수수료 항목
- 라이더 지갑
- 미수금 차감
- 출금 사이클

반영 후 오류는 대상 ID와 금액을 추적한 뒤 본사 최고 관리자의 수동 조정과 감사 로그로 처리합니다.

## 17. 문서 유지관리

현재 `LOGIC.md`의 일부 메뉴 상태는 실제 코드보다 오래되었습니다. 특히 다음 항목은 코드 확인을 우선합니다.

- 라이더 홈 월 정산 합계: 현재 실데이터
- 라이더 정산 달력: 현재 DB 연동
- 라이더 정산 목록·샘플 상세: 목업
- 대표·서브계정: 구현됨
- 출금 수수료 사이클 계산: 구현됨
- 정산 반영 시 PG 자동충전: 미연결

기능 변경 시 이 문서에서 제한사항이 해소되었는지 확인하고 해당 항목을 삭제하거나 갱신합니다.
