# 관리자 매뉴얼

## 1. 로그인과 권한

관리자 사이트에 접속하여 발급받은 아이디와 비밀번호로 로그인합니다. 로그인 후 메뉴가 예상보다 적다면 계정의 조직, 역할, 권한 설정을 먼저 확인하십시오.

### 조직별 사용 범위

- 본사: 전체 대리점 조회, 조직·계정·권한·코드·수수료 등 시스템 관리
- 총판: 소속 대리점 조회와 허용된 업무 처리
- 대리점: 자기 라이더·정산·출금·결제 설정 처리

### 역할별 기본 업무

- 최고 관리자: 조직과 시스템 설정, 수동 조정, 감사 로그
- 총괄 관리자: 소속 조직의 전체 일반 업무
- 운영: 출금, 라이더, 콘텐츠
- 정산: 정산 업로드·반영, 수수료, 공제, 프로모션
- 조회 전용: 권한 관리에서 허용된 조회

실제 권한은 **시스템 관리 > 권한 관리**에서 변경될 수 있습니다. 메뉴는 보이지만 저장이 거절된다면 조회 권한만 부여된 상태입니다.

## 2. 대시보드

### 대리점 대시보드

활성 라이더 수, 정산 금액, 배달 건수, 출금 대기 건, 플랫폼별 실적과 최근 업로드를 확인합니다.

1. 조회 시작일과 종료일을 선택합니다.
2. 핵심 지표와 플랫폼별 합계를 확인합니다.
3. 출금 대기 또는 최근 업로드 항목을 눌러 상세 화면으로 이동합니다.
4. 이상 금액이 있으면 업로드 상세와 수수료 내역을 함께 확인합니다.

### 본사·총판 대시보드

대리점별 실적, 출금 위험, 미처리 항목과 총판별 합계를 확인합니다. 본사는 전체 조직, 총판은 소속 대리점만 표시됩니다.

## 3. 정산 업로드

### 3.1 업로드 전 준비

- 대상 대리점과 플랫폼을 확인합니다.
- 지원 파일은 `.xlsx`입니다.
- 암호화 파일이면 **정산 엑셀 암호**가 등록되어 있어야 합니다.
- 같은 대리점·플랫폼·귀속일·팀/지역 파일을 중복 업로드하지 않습니다.
- 파일명만 믿지 말고 파일 내부 데이터와 선택한 플랫폼을 확인합니다.

### 3.2 미리보기와 매칭

1. **정산 업로드 > 엑셀 업로드**로 이동합니다.
2. 상위 조직 계정이면 대상 대리점을 선택합니다.
3. 파일, 플랫폼, 귀속일, 팀명 또는 지역명을 입력합니다.
4. **미리보기·매칭 확인**을 누릅니다.
5. 총 건수, 금액, 자동 감지 플랫폼과 매칭 결과를 확인합니다.
6. 미매칭 항목은 다음 중 하나로 처리합니다.
   - 기존 라이더 연결: 등록된 라이더를 검색하여 연결
   - 빠른 등록: 신규 라이더를 등록하고 플랫폼 ID 연결
7. 잘못된 플랫폼 경고가 표시되면 선택값과 파일을 다시 확인합니다. 의도한 파일일 때만 확인 절차를 진행합니다.
8. 매칭 결과와 합계가 정상일 때 **확정 저장**을 누릅니다.

쿠팡은 주로 성함, 배민은 UserID로 매칭합니다. 같은 이름이 있어도 다른 대리점 라이더와 연결되지 않도록 대리점 범위가 적용됩니다.

### 3.3 중복 업로드 오류

다음 조건이 같으면 중복으로 판단될 수 있습니다.

- 대리점, 팀/지역, 귀속일, 플랫폼
- 파일명
- 파일 내용의 SHA256

기존 파일이 잘못된 경우 새 파일을 반복 업로드하지 말고 업로드 상세와 DB 정정 절차를 확인하십시오.

## 4. 업로드 상세와 정산 반영

### 4.1 상세 검증

1. **정산 업로드 > 업로드 이력**에서 대상 파일을 선택합니다.
2. 귀속일, 플랫폼, 대리점, 팀/지역, 총 금액을 확인합니다.
3. 매칭/미매칭 필터로 연결되지 않은 라이더를 확인합니다.
4. 쿠팡 파일은 오더별 상세 건수가 함께 들어왔는지 확인합니다.
5. 주간 차감 데이터가 있다면 **차감정보 등록**을 실행합니다.
6. 필요하면 업로드 데이터를 엑셀로 내려받아 원본과 대조합니다.

### 4.2 정산 반영

1. 미매칭과 금액 이상 여부를 먼저 해결합니다.
2. **정산 반영·수수료·지갑**을 누릅니다.
3. 처리 결과의 반영 라이더 수, 수수료, 공제, 순지급액을 확인합니다.
4. **정산 수수료 내역**에서 라이더별 결과를 재확인합니다.
5. 라이더 앱에서 해당 일자의 정산이 표시되는지 확인합니다.

정산 반영 시 라이더별 정산 사이클과 수수료 항목이 생성되고 순지급액이 라이더 지갑에 적립됩니다. 미매칭 행은 반영되지 않습니다.

### 4.3 반영 후 추가 매칭

반영 이후 새로 연결한 라이더가 있다면 **재반영**을 실행합니다. 이미 반영된 라이더를 중복 적립하지 않고 신규 매칭분을 추가 처리하는 용도입니다.

반영 완료 데이터는 단순 삭제로 되돌리지 마십시오. 지갑, 수수료, 미수금 원장에 영향이 있으므로 본사 최고 관리자의 수동 조정과 감사 로그를 사용합니다.

## 5. 정산 조회와 검증

### 업로드 이력

기간, 플랫폼, 검색어로 파일 처리 이력을 조회합니다. 파일 저장 여부와 정산 반영 여부를 구분해서 확인합니다.

### 정산 수수료 내역

기간별 정산 총액, 공제, 순지급액과 라이더별 사이클을 확인합니다. 행을 선택하면 수수료 상세로 이동합니다.

### 수수료·차감 통합

출금 시점의 정산수수료와 정산 반영 시점의 보험료·미수금 등을 함께 확인합니다. 항목의 발생 시점이 서로 다르다는 점에 주의하십시오.

### 원천세 명세

원천세 적용 라이더와 기간별 금액을 확인합니다. 원천세 설정은 라이더 상세에서 관리합니다.

### 플랫폼 수수료 내역

PG 결제 기록과 본사·총판·대리점 분배 스냅샷을 확인합니다. 현재 외부 PG는 Mock이므로 실제 카드 승인 내역과 동일하다고 가정하지 않습니다.

### 오더별 상세 내역

기간, 대리점, 플랫폼, 라이더, 업로드별로 주문 단위 원본을 조회하고 필요하면 엑셀로 내보냅니다.

## 6. 수수료와 공제 설정

### 선공제(대행 수수료)

선정산 라이더에게 정산 반영 시 적용할 건당 금액을 설정합니다.

1. **선공제(대행 수수료)**로 이동합니다.
2. 적립일수 구간과 단기·장기 금액을 입력합니다.
3. 저장 후 다음 정산 반영부터 적용되는지 확인합니다.

### 미수금 원장

대여금, 리스, 선지급을 수수료와 분리하여 관리합니다.

1. 라이더를 선택합니다.
2. 종류, 원금, 시작일, 종료 예정일, 메모를 입력합니다.
3. 수동 차감 또는 리스 자동 차감 결과를 원장 항목에서 확인합니다.
4. 잘못된 항목은 이력과 정산 반영 여부를 확인한 뒤 수정·취소합니다.

### 수수료 설정

본사 최고 관리자는 대리점별 출금수수료와 플랫폼 수수료 분배값을 관리합니다. 출금수수료, 선정산 대행 수수료, 플랫폼 수수료는 서로 다른 항목입니다.

## 7. 라이더 관리

### 신규 등록

1. **라이더 > 라이더 관리**로 이동합니다.
2. 라이더 등록을 선택합니다.
3. 이름, 전화번호, 플랫폼 ID, 계좌와 필요한 정보를 입력합니다.
4. 생성된 로그인 아이디를 라이더에게 전달합니다.
5. 초기 비밀번호 정책에 따라 최초 로그인 후 비밀번호 변경을 안내합니다.

### 상세 관리

라이더 상세에서 다음 항목을 확인·변경합니다.

- 활동 상태
- 쿠팡·배민 등 플랫폼 ID
- 계좌 정보
- 원천세 적용 여부
- 선정산/주정산 구분
- 출금 보류
- 미수금 원장
- 관리자 메모

상위 조직은 조회할 수 있어도 수정 권한이 제한될 수 있습니다. 라이더 계좌 변경은 라이더 앱이 아니라 관리자 화면에서 처리합니다.

## 8. 프로모션 지급

프로모션은 정산 업로드와 별도의 PG 결제·지갑 적립 흐름입니다.

1. **프로모션 지급**에서 템플릿을 내려받습니다.
2. 라이더별 지급액을 입력한 뒤 파일을 업로드합니다.
3. 미리보기에서 매칭, 미매칭, 0원 항목을 확인합니다.
4. 지급 확정을 실행합니다.
5. 상세 화면에서 성공·실패를 확인합니다.
6. 실패 건은 원인을 확인한 뒤 재시도합니다.

현재 PG 연동은 Mock이므로 운영 전 실제 결제 연동 상태를 별도로 확인해야 합니다.

## 9. 출금 처리

### 9.1 주정산 라이더

1. 라이더가 앱에서 출금을 신청합니다.
2. **출금 > 출금 신청 목록**에서 계좌, 금액, 수수료, 신청 기간을 확인합니다.
3. 잘못된 신청은 사유를 입력해 반려합니다.
4. 정상 신청은 **다운로드**에서 신한 BizBank용 파일을 생성합니다.
5. 은행 시스템에서 실제 이체를 처리합니다.
6. 이체 성공 건만 **입금 완료** 또는 일괄 완료 처리합니다.
7. 완료 내역에서 상태와 처리 시각을 확인합니다.

파일 다운로드만으로 실제 은행 이체가 완료되는 것은 아닙니다. 은행 처리 결과를 확인하기 전에 완료로 변경하지 마십시오.

### 9.2 출금 정책

대리점은 출금 신청 목록의 설정 버튼에서 보증금과 건당 수수료를 설정할 수 있습니다. 사이드바에 별도 메뉴가 없을 수 있습니다.

### 9.3 선정산 라이더

1. **출금 > 일일정산 지급**으로 이동합니다.
2. 지급 대상과 대리점 지갑 잔액을 확인합니다.
3. 개별 또는 일괄 지급을 실행합니다.
4. 성공·실패 결과를 확인합니다.

대리점 지갑 잔액이 부족하면 지급할 수 없습니다. 현재 오픈뱅킹은 Mock 상태입니다.

### 9.4 대리점 자체 인출과 결제 설정

대리점 계정에서 등록 카드, 출금 계좌, 대리점 지갑을 관리합니다. 카드 충전과 계좌 이체는 외부 연동 상태를 확인한 뒤 사용하십시오.

## 10. 콘텐츠 관리

### 공지

본사에서 공지를 작성하고 노출 범위와 기간을 지정합니다. 총판·대리점 계정은 권한이 있어도 작성이 제한될 수 있습니다.

### 광고 배너

이미지, 링크, 노출 슬롯과 기간을 지정합니다. 업로드 전에 개인정보와 민감정보가 이미지에 포함되지 않았는지 확인합니다.

## 11. 조직·계정·권한

### 조직 관리

본사 최고 관리자만 총판과 대리점을 생성·수정합니다. 조직 생성 시 대표 관리자와 기본 설정·지갑이 함께 준비될 수 있으므로 중복 생성하지 않습니다.

### 대표·서브계정

총판 또는 대리점의 대표계정은 자기 조직의 서브계정을 관리합니다. 대표계정은 해당 조직에서 가장 먼저 생성된 관리자 계정을 기준으로 판별됩니다.

### 관리자 계정과 권한 관리

1. 시스템 관리에서 관리자 계정의 조직과 역할을 확인합니다.
2. 권한 관리에서 역할별 영역의 조회·쓰기 권한을 설정합니다.
3. 테스트 계정으로 메뉴 노출과 저장 가능 여부를 확인합니다.

시스템 관리 메뉴는 일반 역할 권한표와 별개로 최고 관리자에게만 허용됩니다.

## 12. 코드·감사·수동 조정

### 코드/마스터

은행, 플랫폼, 상태값 등 공통 코드를 관리합니다. DB enum, PHP 상태 처리와 함께 사용되므로 임의 삭제하거나 코드값을 변경하지 마십시오.

### 감사 로그

로그인, 설정 변경, 정산·출금 처리 등 주요 작업을 조회하고 CSV로 내보냅니다. 사고 조사 시 작업자, 시각, action, 대상 ID를 함께 확인합니다.

### 정산/잔액 수동 조정

본사 최고 관리자만 사용합니다.

1. 조정 대상 라이더 또는 대리점을 선택합니다.
2. 조정 종류와 금액을 확인합니다.
3. 추적 가능한 상세 사유를 입력합니다.
4. 실행 후 지갑과 감사 로그를 함께 검증합니다.

수동 조정은 원본 업로드를 수정하는 기능이 아닙니다. 원인과 보정 내역을 모두 남겨야 합니다.

## 13. 자주 발생하는 문제

### 파일이 열리지 않음

- PHP zip 확장과 PhpSpreadsheet 설치 확인
- 암호화 파일이면 정산 엑셀 암호 확인
- `.xlsx` 파일인지 확인

### 플랫폼 불일치 경고

선택한 플랫폼과 파일 파싱 결과가 다릅니다. 파일을 다시 선택하거나 플랫폼 값을 바로잡습니다.

### 미매칭이 많음

- 대상 대리점이 맞는지 확인
- 배민 UserID와 쿠팡 라이더명이 등록되어 있는지 확인
- 기존 라이더 연결 후 미리보기를 다시 실행

### 정산이 라이더 앱에 안 보임

- 업로드 저장만 하고 정산 반영을 실행하지 않았는지 확인
- 해당 행이 미매칭인지 확인
- 반영 후 연결했다면 재반영 확인

### 출금 완료 처리가 안 됨

- 계정에 출금 쓰기 권한이 있는지 확인
- 신청 상태가 `downloaded`인지 확인
- 이미 완료·반려된 건인지 확인

### 일일정산 지급 실패

- 대리점 지갑 잔액 확인
- 라이더 계좌와 상태 확인
- Mock 오픈뱅킹 결과와 앱 로그 확인
