# 업무 흐름 참조서

## 1. 정산 전체 흐름

```text
라이더·플랫폼 ID 등록
→ 정산 엑셀 미리보기
→ 라이더 자동/수동 매칭
→ 업로드 확정 저장
→ 상세 검증과 차감 등록
→ 정산 반영
→ 라이더별 수수료·공제 계산
→ 라이더 지갑 적립
→ 라이더 정산 조회
→ 출금 또는 일일정산 지급
```

### 각 단계의 완료 기준

1. **라이더 등록**: 소속 대리점, 로그인 정보, 플랫폼 ID가 정확함
2. **미리보기**: 플랫폼, 귀속일, 팀/지역, 합계가 원본과 일치함
3. **매칭**: 미매칭 원인을 확인하고 잘못된 타인 연결이 없음
4. **확정 저장**: 업로드 이력과 원본 상세가 생성됨
5. **정산 반영**: 라이더별 사이클·수수료 항목·지갑 적립이 생성됨
6. **지급**: 은행 이체 또는 선정산 지급 결과가 완료 상태임

## 2. 업로드 데이터 구조

`settlement_uploads`는 업로드 1건의 헤더입니다. 하위에는 다음 데이터가 저장됩니다.

- `settlement_daily_riders`: 라이더별 일간 요약
- `settlement_order_details`: 주문 단위 상세
- `settlement_hourly_insurance`: 시간제 보험
- `settlement_support_amounts`: 지원금
- `settlement_weekly_deductions`: 주간 차감 원본

정산 반영 후 생성되는 주요 데이터는 다음과 같습니다.

- `settlement_rider_cycles`: 라이더·정산일·플랫폼·팀/지역별 확정 사이클
- `settlement_fee_items`: 수수료·보험료·공제 항목
- `rider_wallets`: 라이더 임시 잔액

## 3. 라이더 매칭

### 기본 식별값

- 쿠팡: 주로 라이더 성함
- 배민: UserID

### 매칭 원칙

- 반드시 대상 대리점 범위 안에서 찾습니다.
- 동일 이름은 전화번호와 플랫폼 ID를 추가 확인합니다.
- 신규 라이더는 빠른 등록 후 플랫폼 ID를 연결합니다.
- 반영 후 연결된 행은 재반영으로 추가 처리합니다.
- 미매칭 행은 정산 반영에서 제외됩니다.

## 4. 정산 금액 계산

정산 반영은 플랫폼 지급액이 있으면 해당 값을 기준으로 하고, 없으면 총액을 기준으로 수수료·공제를 계산합니다.

```text
기준 정산액
- 선정산 대행 수수료
- 원천세
- 고용보험
- 산재보험
- 시간제 보험
- 등록된 차감
- 미수금 상환
= 순지급액
```

순지급액이 라이더 지갑에 적립됩니다.

## 5. 금액 항목 구분

### 정산수수료

- 발생 시점: 라이더 출금
- 기준: 출금 대상 정산의 주문 건수와 경과 기간
- 관리: 대리점별 출금 정책

### 선정산 대행 수수료

- 발생 시점: 선정산 라이더의 정산 반영
- 기준: 적립일수 구간과 건당 금액
- 관리: 선공제(대행 수수료)

### 플랫폼 수수료

- 발생 시점: PG 카드 결제
- 기준: 결제 금액과 본사·총판·대리점 분배율
- 관리: 시스템 수수료 설정

### 보험료

- 발생 시점: 정산 반영
- 종류: 고용, 산재, 시간제 보험

### 미수금

- 발생 시점: 원장 등록 후 정산 반영 또는 수동 차감
- 종류: 대여금, 리스, 선지급
- 성격: 원금 상환이며 수수료가 아님

## 6. 주정산 출금 흐름

```text
라이더가 종료 정산일 선택
→ 출금 미리보기
→ 보증금과 정산수수료 계산
→ 신청 생성(pending)
→ 정산 사이클 점유
→ 관리자가 이체 파일 다운로드(downloaded)
→ 은행에서 실제 이체
→ 관리자가 완료 처리(completed)
→ 라이더 지갑 차감
```

### 반려

```text
pending 또는 downloaded
→ 관리자 반려 사유 입력
→ rejected
→ 정산 사이클 점유 해제
→ 라이더 재신청 가능
```

### 수수료 계산

출금 가능한 오래된 정산부터 선택한 종료일까지 누적합니다. 대리점별 정책에 따라 최근 구간과 장기 구간의 건당 수수료가 다를 수 있습니다.

### 중요한 시점

- 신청 시: 사이클을 점유하지만 지갑 잔액은 차감하지 않음
- 완료 시: 실지급액과 수수료를 지갑에서 차감
- 반려 시: 사이클 점유를 해제

## 7. 선정산 지급 흐름

```text
선정산 라이더 정산 반영
→ 라이더 지갑 적립
→ 대리점 지갑 잔액 확인
→ 관리자가 일일정산 지급 실행
→ 오픈뱅킹 이체(Mock)
→ 대리점 지갑 차감
→ 지급 완료 기록
```

대리점 지갑에 충분한 금액이 있어야 합니다. 현재 외부 금융 연동은 Mock입니다.

## 8. 대리점 지갑과 PG

```text
대리점 카드 등록
→ PG 결제(Mock)
→ 플랫폼 수수료 분배 스냅샷
→ agency_wallets 충전
→ 일일정산 지급 또는 대리점 인출
→ agency_wallet_ledger 기록
```

현재 정산 반영이 자동으로 PG 충전을 호출하지 않습니다. 프로모션 지급과 결제 설정의 수동 충전 등 실제 호출 경로를 구분해야 합니다.

## 9. 프로모션

```text
템플릿 다운로드
→ 라이더별 금액 입력
→ 업로드·미리보기
→ 매칭 검증
→ 지급 확정
→ 라이더별 PG 결제(Mock)
→ 성공 건 라이더 지갑 적립
→ 실패 건 상세에서 재시도
```

정산 파일과 별도 배치이며 성공한 지급만 지갑에 반영됩니다.

## 10. 미수금

```text
라이더 미수금 원장 등록
→ 대여금/리스/선지급 구분
→ 수동 상환 또는 리스 기간 자동 차감
→ deduction_entries 생성
→ 정산 반영 시 공제
→ rider_debt_entries 원장 기록
```

미수금 원금, 상환액, 잔액이 일치하는지 정산 통합 보고서와 원장을 함께 확인합니다.

## 11. 조직과 권한 흐름

```text
본사 최고 관리자
→ 총판·대리점 조직 생성
→ 조직 대표계정 생성
→ 대표계정이 서브계정 생성
→ 역할 부여
→ 역할별 영역 조회·쓰기 권한 적용
→ 조직 스코프로 데이터 제한
```

권한 판단에는 역할 권한과 조직 데이터 범위가 동시에 적용됩니다. 쓰기 권한이 있어도 타 조직 데이터는 변경할 수 없습니다.

## 12. 주요 상태 전이

### 라이더

```text
active
→ suspended
→ active

active
→ leave_request
→ offboarded
```

### 출금

```text
pending → downloaded → completed
pending → rejected
downloaded → rejected
```

### 정산

```text
업로드 미리보기
→ 확정 저장(parsed)
→ 정산 반영
→ 필요 시 신규 매칭분 재반영
```

## 13. 감사와 정정

정산·지갑·출금은 여러 원장에 연결됩니다. 오류가 발생했을 때 원본 행을 임의 삭제하거나 금액을 직접 UPDATE하지 않습니다.

권장 절차:

1. 업로드 ID, 라이더 ID, 정산일, 출금 ID를 확보합니다.
2. 업로드 원본과 정산 사이클을 비교합니다.
3. 수수료 항목, 지갑 원장, 출금 상태를 확인합니다.
4. 본사 최고 관리자가 수동 조정으로 보정합니다.
5. 상세 사유와 근거를 감사 로그에 남깁니다.
6. 보정 후 관리자 화면과 라이더 화면의 합계를 재검증합니다.
