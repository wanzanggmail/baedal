# 도깨비 배달 솔루션 매뉴얼

이 문서는 도깨비 배달 솔루션을 사용하는 관리자, 라이더, 운영·개발 담당자를 위한 매뉴얼의 시작점입니다.

## 문서 구성

- [관리자 매뉴얼](ADMIN_MANUAL.md): 본사·총판·대리점의 메뉴와 업무 처리 절차
- [라이더 매뉴얼](RIDER_MANUAL.md): 로그인, 정산 확인, 출금 신청, 내 정보
- [설치·운영 매뉴얼](OPERATIONS_MANUAL.md): 설치, 배포, DB, 백업·복구, 장애 대응
- [업무 흐름 참조서](WORKFLOW_REFERENCE.md): 정산·수수료·공제·프로모션·출금의 처리 구조
- [현재 제약 및 주의사항](KNOWN_LIMITATIONS.md): 목업 화면, Mock 연동, 문서와 구현의 차이

## 시스템 개요

도깨비 배달은 플랫폼 정산 파일을 대리점별로 업로드하고 라이더와 연결한 뒤, 수수료와 공제를 계산하여 라이더 지갑에 반영하는 솔루션입니다. 라이더는 자신의 정산과 출금 내역을 확인할 수 있고, 관리자는 조직 범위와 역할 권한에 따라 정산·출금·라이더·콘텐츠를 관리합니다.

기본 업무 흐름은 다음과 같습니다.

1. 본사가 총판과 대리점 조직을 구성합니다.
2. 대리점이 관리자 계정과 라이더를 등록합니다.
3. 정산 담당자가 플랫폼 정산 엑셀을 미리보기하고 라이더를 매칭합니다.
4. 업로드를 확정한 뒤 정산을 반영합니다.
5. 반영 금액이 라이더 지갑과 정산 내역에 기록됩니다.
6. 주정산 라이더는 앱에서 출금을 신청하고, 관리자가 이체 후 완료 처리합니다.
7. 선정산 라이더는 대리점의 일일정산 지급 화면에서 처리합니다.

## 조직과 데이터 범위

조직은 다음 3단계로 구성됩니다.

```text
본사
└─ 총판
   └─ 대리점
      └─ 라이더
```

- **본사**: 전체 총판·대리점 데이터를 조회합니다.
- **총판**: 자신에게 소속된 대리점 데이터만 조회합니다.
- **대리점**: 자기 대리점과 소속 라이더 데이터만 조회합니다.
- **라이더**: 본인의 정산·출금·프로모션·미수금만 조회합니다.

같은 메뉴라도 로그인한 조직과 역할에 따라 표시 여부, 조회 범위, 수정 가능 여부가 달라집니다. 상위 조직에서 조회되지 않는 다른 조직의 데이터는 오류가 아니라 정상적인 권한 제한입니다.

## 관리자 역할

- **최고 관리자(`super`)**: 전체 메뉴와 시스템 관리 기능을 사용합니다.
- **총괄 관리자(`manager`)**: 소속 조직 범위의 일반 업무 메뉴를 조회·수정합니다. 시스템 관리 메뉴는 사용할 수 없습니다.
- **운영(`operation`)**: 기본 권한 설정상 출금·콘텐츠·라이더 업무를 처리합니다.
- **정산(`settlement`)**: 기본 권한 설정상 정산·선공제·프로모션 업무를 처리합니다.
- **조회 전용(`admin`)**: 권한 관리에서 허용된 영역을 조회합니다.

`super`와 `manager`를 제외한 역할의 실제 권한은 **시스템 관리 > 권한 관리** 설정에 따라 달라질 수 있습니다.

## 공통 용어

### 정산 반영

업로드한 원본 데이터를 라이더별 정산 사이클로 확정하고 수수료·공제를 계산하여 라이더 지갑에 적립하는 작업입니다. 파일을 업로드만 한 상태에서는 라이더 앱에 표시되지 않습니다.

### 정산수수료

라이더가 출금할 때 정산 건수와 경과 기간을 기준으로 계산되는 수수료입니다. 대리점 정책에 따라 금액이 달라질 수 있습니다.

### 플랫폼 수수료

PG 카드 결제 금액에서 본사·총판·대리점 몫으로 분배되는 수수료입니다. 라이더 출금 시 계산되는 정산수수료와 다릅니다.

### 보험료

고용보험, 산재보험, 시간제 보험 등 정산 반영 단계에서 차감되는 항목입니다.

### 미수금

대여금, 리스, 선지급 등 라이더가 상환해야 하는 원금입니다. 수수료가 아니며 미수금 원장에서 관리합니다.

### 선정산과 주정산

- **선정산(일일정산)**: 대리점 관리자가 일일정산 지급 메뉴에서 라이더에게 지급합니다.
- **주정산**: 라이더가 앱에서 출금을 신청하고 관리자가 은행 이체와 완료 처리를 진행합니다.

### 미매칭

정산 파일의 라이더 식별값과 등록된 라이더가 연결되지 않은 상태입니다. 쿠팡은 주로 성함, 배민은 UserID를 사용하며 대리점 범위 안에서 매칭합니다.

## 상태값 빠른 이해

### 라이더 상태

- `active`: 정상 이용
- `suspended`: 일시 정지
- `leave_request`: 탈퇴 처리 중
- `offboarded`: 계약 종료

### 출금 상태

- `pending`: 신청 대기
- `downloaded`: 이체 파일 다운로드 또는 처리 진행
- `completed`: 이체 완료
- `rejected`: 반려

### 업로드와 정산 상태

업로드 저장과 정산 반영은 별도 단계입니다. 업로드 이력에서 파일이 보여도 **정산 반영**을 실행하지 않았다면 라이더 지갑과 앱 정산 내역에는 반영되지 않습니다.

## 문서 사용 원칙

- 화면 동작은 현재 코드 구현을 기준으로 설명합니다.
- 외부 PG·오픈뱅킹 연동은 현재 Mock 상태이므로 실제 금융 처리로 간주하지 않습니다.
- 목업 화면은 운영 판단이나 금액 검증에 사용하지 않습니다.
- 계정 비밀번호, DB 비밀번호, 은행 계좌번호 등 민감정보를 문서나 화면 캡처에 남기지 않습니다.
- 기능 변경 후에는 `LOGIC.md`, `DB_SCHEMA.md`와 이 매뉴얼을 함께 확인합니다.
