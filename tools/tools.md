# tools — 운영 도구 설명서

`tools/` 폴더의 PHP 스크립트는 **관리자 화면에 없는 작업**을 서버에서 직접 처리할 때 쓰는 명령줄 도구입니다.
모두 프로젝트 루트에서 `php tools/<파일명>` 으로 실행하고, 접속하는 DB 는 서버의 `.env` 설정을 따릅니다.
그래서 **어느 서버에서 실행하느냐에 따라 테스트 DB 가 바뀔 수도, 실서버 DB 가 바뀔 수도 있습니다.**

모든 도구가 첫 줄에 `DB: <DB 이름>` 을 출력합니다. **실행 전에 반드시 이 이름부터 확인하세요.**

| [`reset_settlements.php`](#reset_settlementsphp--정산-내역-초기화) | 라이더·조직은 두고 정산 내역만 초기화 | 대량 삭제, 지갑 0 | **매우 높음** |

### 공통 규칙

- **데이터를 바꾸는 도구는 전부 기본이 미리보기입니다.** 옵션 없이 실행하면 무엇이 바뀔지만 보여 주고 아무것도 바꾸지 않습니다.
- 실제로 반영하려면 `--apply` 가 필요합니다. 되돌릴 수 없는 삭제 도구는 확인 옵션(`--yes-...`)을 **하나 더** 붙여야 실행됩니다.
- 삭제·초기화 도구는 **하나의 트랜잭션**으로 실행됩니다. 중간에 실패하면 전부 롤백되고, 일부만 지워진 상태로 남지 않습니다.
- **실서버에서 삭제 도구를 돌리기 전에는 반드시 DB 백업부터 하세요.**

### 권장 순서

```
① 미리보기 실행 → ② 출력의 DB 이름·대상·건수 확인 → ③ DB 백업 → ④ --apply 실행 → ⑤ 감사 도구로 검증
```

## audit_consistency.php — 정산 정합성 전수 대사

**같은 정산을 관리자 화면과 라이더 화면이 다르게 보여 주는 곳이 있는지** 찾아냅니다.
테스트용 가짜 데이터가 아니라 DB 에 쌓인 **실제 정산 사이클 전부**를 검사합니다.

**읽기 전용**이라 운영 중인 실서버에서 그대로 실행해도 됩니다.

### 사용법

```bash
php tools/audit_consistency.php                     # 전체 검사
php tools/audit_consistency.php --since=2026-03-04  # 이 날짜 이후 정산만 검사
php tools/audit_consistency.php --rider=12          # 라이더 id 12 한 명만
php tools/audit_consistency.php --limit=30          # 라이더 앞 30명만 (빠른 확인)
```

| 옵션 | 설명 |
|---|---|
| `--since=YYYY-MM-DD` | 이 날짜 이후 정산만 검사합니다. 산식이 바뀌기 전의 옛 데이터를 빼고 **현재 계산 로직으로 만든 데이터만** 볼 때 씁니다. 형식이 틀리면 종료코드 2로 끝납니다. |
| `--rider=<id>` | 라이더 한 명만 검사합니다. 특정 라이더가 금액이 이상하다고 할 때 씁니다. |
| `--limit=<N>` | 앞에서부터 N명만 검사합니다. 배포 직후 빠르게 확인할 때 씁니다. |

### 검사 항목

| 번호 | 항목 | 확인 내용 |
|---|---|---|
| ① | 원장 항등식 | 사이클마다 공제 항목 합이 `total_fee_amount` 와 같은지, 실수령액이 음수가 아닌지 |
| ② | 세금 재검산 | 선차감이 적용된 사이클의 원천세를 다시 계산해 봅니다. 과세표준은 `정산액 + 지원금 − 선차감` 입니다. |
| ③ | 관리자 vs 라이더 | 라이더마다 관리자 집계와 라이더 앱 집계를 8개 항목(정산금액·공제·실수령 등)으로 대조합니다. |
| ④ | 정산수수료 구성 | `전역 고정분(본사+세무대리+개발사) + 총판·대리점 추가분 = 총액` 이 맞는지 대리점마다 확인합니다. |
| ⑤ | 출금 정합성 | 출금 신청 금액·수수료·부담 주체가 서로 맞는지 확인합니다. |
| ⑥ | 오더별 상세 합 | 라이더가 오더 목록을 직접 더했을 때 정산금액과 같은지 확인합니다. |
| ⑦ | 지갑 잔액 대사 | 라이더 지갑 잔액이 적립·출금 내역과 맞는지 확인합니다. |

### 결과 읽는 법

마지막에 `검사 N건 · 통과 N · 불일치 N` 이 나오고, 이상이 없으면 **`정합성 이상 없음.`** 으로 끝납니다.
불일치가 있으면 항목별로 묶어서 앞의 5건을 보여 줍니다(예: `라이더26 2026-03-03 (사이클 20,477 / 주문합 19,032)`).

**종료코드**: 불일치가 0건이면 `0`, 하나라도 있으면 `1` 입니다.

**「참고」로 표시되는 항목은 오류가 아닙니다.** 이미 원인을 알고 있는 옛 데이터라서 따로 분류해 둔 것입니다.

| 참고 항목 | 원인 |
|---|---|
| `gross+지원−공제 ≠ 실수령` 인 사이클 | 산식이 여러 번 바뀌었는데 예전 사이클은 다시 계산하지 않았습니다. 화면은 `실수령 + 공제 − 지원금` 으로 거꾸로 계산해서 보여 주므로 **라이더에게는 어긋나 보이지 않습니다.** |
| 오더 합이 정산금액의 1/1.1 인 날짜 | 부가세를 정산액에 포함하던 시절의 데이터입니다. |
| 2026-03-04 이전 오더 합 차이 | 시범운영 기간 쿠팡 원본 파일에서부터 요약시트와 오더시트 금액이 달랐습니다. 계산 문제가 아닙니다. |
| 선차감 총액 | 관리자에게는 보이고 라이더에게는 보이지 않는 대리점 몫의 합계입니다. 정보 표시용입니다. |

### 언제 쓰나

- **배포 직후**: 특히 정산·수수료·세금 계산 코드를 바꿨을 때
- 라이더가 "앱 금액이 명세서랑 다르다"고 문의할 때 (`--rider=`)
- 정산 엑셀을 대량으로 업로드한 뒤

## audit_money.php — 돈 흐름 불변식 감사

**돈이 한쪽에는 쌓였는데 다른 쪽 집계에서는 빠지는 누락**을 실제 데이터로 찾아냅니다.
`audit_consistency.php` 가 "두 화면이 같은 숫자를 보여 주는가"를 본다면, 이 도구는 **"돈이 새는가"**를 봅니다.

**읽기 전용**입니다.

### 사용법

```bash
php tools/audit_money.php
```

옵션은 없습니다.

### 검사 항목

| 번호 | 항목 | 확인 내용 |
|---|---|---|
| ① | 원천세 예수금 | 대리점 예수금이 `발생액(정산 + 프로모션) − 세무대리 수집액` 과 같은지 |
| ② | 고용·산재 예수금 | 0 인지 확인합니다. 2026-09-04 정정으로 고용·산재는 대리점이 갖는 돈이 됐습니다. |
| ③ | 지갑 원장 | 대리점 지갑 잔액이 `입금 합 − 출금 합` 과 같은지 |
| ④ | 공제 합계 | 정산 사이클의 `total_fee_amount` 가 공제 항목 합과 같은지 |
| ⑤ | 실수령액 | `net_amount == gross + 지원금 − 공제` 인지 |
| ⑥ | 공제 코드 누락 | 명세서나 집계에서 처리하지 않는 공제 코드가 있는지 |
| ⑥-B | 차감 누수 | 공제 합이 정산액보다 커서 사라져 버린 금액이 있는지 |
| ⑦ | 음수 잔액 | 잔액이 마이너스인 지갑이 있는지 (자금 부족 신호) |
| ⑧ | 인출 가능액 | `잔액 − 라이더 채무 − 원천세 예수금` 을 대리점별로 보여 줍니다. |

### 결과 읽는 법

- `[OK]` 통과 · `[WARN]` 확인이 필요하지만 오류는 아님 · `[FAIL]` 오류
- **종료코드**: `[FAIL]` 이 하나라도 있으면 `1`, 없으면 `0` 입니다. 스크립트나 CI 에서 결과를 판정할 때 쓸 수 있습니다.
- ③ 지갑 원장에서 FAIL 이 나오면 [`reconcile_ledger.php`](#reconcile_ledgerphp--지갑-원장-보정) 로 보정할 수 있습니다.

### 언제 쓰나

- 정산 병행 테스트 **전과 후**
- 지갑·출금·원천세 관련 코드를 바꾼 뒤
- 삭제·초기화 도구를 실행한 뒤 검증할 때

## gen_enc_key.php — 암호화 키 생성

`.env` 의 `APP_ENC_KEY` 에 넣을 새 암호화 키를 만들어 화면에 출력합니다.
이 키로 **PG 결제키와 라이더 계좌번호**를 AES-256-GCM 으로 암호화해서 저장합니다.

### 사용법

```bash
php tools/gen_enc_key.php
```

출력된 `APP_ENC_KEY=...` 한 줄을 서버 `.env` 에 추가하면 됩니다. DB 는 건드리지 않습니다.

### ⚠️ 반드시 지킬 것

- **서버를 새로 만들 때 딱 한 번만 생성하세요.** 이미 운영 중인 서버의 키를 새 키로 바꾸면 **기존에 암호화된 결제키·계좌번호를 전부 읽을 수 없게 됩니다.**
- **웹서버가 여러 대면 모두 같은 키**를 넣어야 합니다. 키가 다르면 다른 서버가 저장한 값을 읽지 못합니다.
- **키를 잃어버리면 복구할 방법이 없습니다.** 비밀번호 관리자나 AWS Secrets Manager 에 따로 보관하세요.
- 키를 채팅·메일·깃에 올리지 마세요.

## reconcile_ledger.php — 지갑 원장 보정

예전에는 `AgencyWallet::move()` 가 **잔액 변경과 원장 기록을 따로 실행**했습니다.
그래서 잔액은 바뀌었는데 원장 행이 남지 않은 경우가 있었습니다(현재 코드는 수정됨).
이 도구는 그 차액을 `ledger_fix` 원장 행으로 **나중에 기록**해서 `잔액 == 원장 합` 이 다시 맞도록 합니다.

### 사용법

```bash
php tools/reconcile_ledger.php          # 미리보기 — 보정 대상과 금액만 출력
php tools/reconcile_ledger.php --apply  # 실제 반영
```

### 동작 방식

- 대리점 지갑마다 `잔액 − 원장 합` 을 계산해서, 0 이 아닌 곳만 보정 대상으로 잡습니다.
- 차액이 양수면 `credit`(입금), 음수면 `debit`(출금) 원장 행을 추가합니다.
- **잔액(balance)은 절대 바꾸지 않습니다.** 돈은 그대로 두고 기록만 채웁니다.
- **여러 번 실행해도 안전합니다.** 한 번 반영하면 차액이 0 이 되어, 다시 실행해도 `보정할 대상이 없습니다` 로 끝납니다.

### 출력 예 (예시 값)

```
org#13  도깨비           잔액      1,250,000 / 원장합      1,200,000 → 보정 +50,000 (credit)
대상 1개 조직 · 보정 총액 50,000원 (잔액 변동 없음)
```

### 검증

반영한 뒤 `php tools/audit_money.php` 를 실행해서 ③ 지갑 원장 항목이 `[OK]` 인지 확인하세요.

## delete_org.php — 조직 삭제

**아직 실적이 하나도 없는** 총판·대리점을 삭제합니다. 샘플로 만든 조직이나 잘못 만든 조직을 지울 때 씁니다.

관리자 화면에는 조직 삭제 기능이 **일부러 없고 비활성화만 할 수 있습니다.** 조직 id 가 지갑·원장·라이더·정산 기록에 남아 있어서, 지우면 과거 기록이 어느 조직 것인지 알 수 없게 되기 때문입니다.

### 사용법

```bash
php tools/delete_org.php AG-01                          # 미리보기 (조직 코드로 지정)
php tools/delete_org.php 25                             # 미리보기 (조직 id 로 지정)
php tools/delete_org.php AG-01 --apply                  # 실제 삭제
php tools/delete_org.php AG-01 --apply --with-accounts  # 소속 관리자 계정까지 함께 삭제
```

| 인자·옵션 | 설명 |
|---|---|
| `<조직코드 또는 id>` | **필수.** 숫자만 입력하면 id, 그 외에는 조직 코드로 찾습니다. |
| `--apply` | 실제로 삭제합니다. 없으면 미리보기입니다. |
| `--with-accounts` | 그 조직 소속 관리자 계정도 함께 삭제합니다. 이 옵션이 없는데 소속 계정이 있으면 삭제를 거부합니다. |

### 삭제를 거부하는 경우

아래 중 하나라도 해당하면 **아무것도 지우지 않고** 무엇 때문에 막혔는지 알려 줍니다(종료코드 1).

- **본사(admin)·세무대리(tax_agent)**: 시스템 기준 조직이라 삭제할 수 없습니다.
- **하위 조직이 있음**: 자식 조직부터 지워야 합니다. 총판을 지우려면 소속 대리점을 먼저 지우세요.
- **실적이 1건이라도 있음**: 라이더 · 정산 업로드 · 주간 정산 · 프로모션 · 출금 요청 · PG 결제 · 펌뱅킹 이체 · 원천세 수집 · 메시지 발송 · 지갑 원장
- **지갑에 돈이 남아 있음**: 잔액 · 원천세 예수금 · 보험 예수금 중 하나라도 0 이 아니면 거부합니다.
- **소속 관리자 계정이 있는데 `--with-accounts` 를 주지 않음**

실적이 있는 조직은 지우지 말고 **`관리자 > 시스템 > 조직관리` 에서 활성 토글을 끄세요.** 목록과 선택 화면에서 빠집니다.

### 함께 지워지는 것

조직에 딸린 **설정성 데이터**만 함께 지웁니다.
지갑(`agency_wallets`) · 계좌 · 카드 · 출금 설정 · 수수료 설정 · 공제 설정 · 정산 엑셀 설정 · 배너 · 공지

## reset_riders.php — 라이더 전체 삭제

라이더를 **전부 지우고 새로 등록**하고 싶을 때 씁니다. 대리점 하나로 범위를 좁힐 수도 있습니다.

### ⚠️ `riders` 테이블만 지우면 안 되는 이유

라이더 id 는 20개가 넘는 테이블에 들어 있고, 그중 절반은 외래키가 없어서 DB 가 알아서 정리해 주지 않습니다.

| 외래키 종류 | 테이블 예시 | `riders` 만 지우면 |
|---|---|---|
| CASCADE (6개) | 지갑 · 채무 · 차감 · 정산 사이클 · 출금 신청 · 플랫폼 연결 | 조용히 함께 사라지고 기록도 남지 않습니다. |
| SET NULL (6개) | 정산 원본 · 주문 상세 · 지원금 · 주급 공제 · 시간 보험 | 행은 남고 `rider_id` 만 비어서 **누구 것인지 알 수 없는 데이터**가 됩니다. |
| **외래키 없음 (7개)** | PG 결제 · 채무 상환 이력 · 명세서 링크 · 펌뱅킹 이체 · 문자 큐·로그 · 차감 이월 | id 가 그대로 남습니다. **새 라이더가 같은 id 를 받으면 다른 사람의 결제·명세서·문자가 그 라이더에게 붙습니다.** 가장 위험합니다. |

그래서 이 도구는 라이더에 딸린 데이터를 **자식 테이블부터 순서대로 전부** 지웁니다.

### 사용법

```bash
php tools/reset_riders.php                                      # 미리보기 — 전체 대리점
php tools/reset_riders.php --agency=DKKB-0001                   # 미리보기 — 한 대리점만
php tools/reset_riders.php --with-uploads                       # 미리보기 — 업로드 이력까지
php tools/reset_riders.php --apply --yes-delete-riders          # 실제 삭제 — 전체
php tools/reset_riders.php --agency=DKKB-0001 --apply --yes-delete-riders
```

| 옵션 | 설명 |
|---|---|
| `--agency=<코드 또는 id>` | 이 대리점 소속 라이더만 지웁니다. 없으면 **전체 대리점**이 대상입니다. |
| `--with-uploads` | 정산 업로드 이력(`settlement_uploads`)도 함께 지웁니다. 없으면 업로드 이력은 남습니다. |
| `--with-unmatched` | 어느 라이더에게도 연결되지 않은 「미매칭」 정산 원본 행(`rider_id` 가 비어 있는 행)도 지웁니다. **`--agency` 와 함께 쓸 수 없습니다.** 미매칭 행은 어느 대리점 것인지 알 수 없어서, 함께 쓰면 다른 대리점 데이터까지 지워지기 때문입니다. |
| `--apply` | 실제로 삭제합니다. |
| `--yes-delete-riders` | **삭제 확인 옵션.** `--apply` 만 주면 실행하지 않습니다(종료코드 2). |

미리보기를 실행하면 마지막에 **지금 준 옵션 그대로 실제 삭제하는 명령어**를 출력해 줍니다. 그대로 복사해서 쓰면 됩니다.

### 지우지 않는 것

조직 · 관리자 계정 · 수수료/출금 설정 · 코드마스터 · 대리점 지갑(`agency_wallets`)

### 실행 후

라이더를 다시 등록하고, 필요하면 정산 엑셀을 다시 업로드하세요. 마지막으로 `audit_money.php` 로 확인합니다.

## reset_settlements.php — 정산 내역 초기화

**라이더와 조직은 그대로 두고 정산 내역만** 처음 상태로 되돌립니다.
실서버에서 병행 테스트 데이터를 비우고 실제 운영을 시작할 때 씁니다.

### 사용법

```bash
php tools/reset_settlements.php                                   # 미리보기
php tools/reset_settlements.php --apply --yes-reset-settlements   # 실제 초기화
```

| 옵션 | 설명 |
|---|---|
| `--apply` | 실제로 초기화합니다. |
| `--yes-reset-settlements` | **초기화 확인 옵션.** `--apply` 만 주면 실행하지 않습니다(종료코드 2). |

### 미리보기에서 보여 주는 것

- **남는 것**: 라이더 수 · 조직 수
- **사라지는 돈**: 라이더 지갑 잔액 · 대리점 지갑 잔액 · 원천세 예수금 · 미수금 잔액과 건수 · PG 결제 성공 금액과 건수
- **지울 행**: 테이블별 삭제 건수와 합계

### 지우는 것 (24개 테이블)

| 구분 | 내용 |
|---|---|
| 정산 결과 | 공제 항목 · 출금↔정산 연결 · 차감 이월 · 차감 내역 · 정산 사이클 |
| 출금·지급 | 출금 신청 · 펌뱅킹 이체 |
| 자금조달 | PG 결제 |
| 미수금 | **미수금 계약까지 삭제** · 상환 이력 |
| 정산 원본 | 오더별 상세 · 지원금 · 시간제 보험 · 주급 공제 · 주급 라이더 · 일자별 라이더 · 업로드 이력 |
| 기타 | 지갑 원장 · 명세서 공개 링크 · 세무대리 수집 · 프로모션 지급·배치 · 문자·알림톡 큐와 로그 |

지갑은 행을 지우지 않고 **값만 0 으로** 만듭니다.
- 라이더 지갑: 잔액 · 적립일수 → 0
- 대리점 지갑: 잔액 · 원천세 예수금 · 보험 예수금 → 0

### 남기는 것

라이더(계좌·설정 포함) · 조직 · 관리자 계정 · 수수료/출금/공제 **설정** · 코드마스터 · 공지·배너 · 알림톡 템플릿 · **감사 로그**

### ⚠️ 주의

- **되돌릴 수 없습니다.** 실서버라면 반드시 DB 백업부터 하세요.
- **미수금 계약도 함께 지워집니다.** 실제 대여금·선지급 계약이 있다면, 실행 전에 관리자 화면에서 엑셀로 받아 두세요.
- 실행하면 감사 로그에 `SYSTEM.RESET_SETTLEMENTS` 로 삭제 건수와 사라진 금액이 기록됩니다.
- 끝나면 라이더 수·조직 수가 그대로인지, 정산 사이클이 0 인지, 지갑 잔액이 0 인지 자동으로 확인해서 보여 줍니다.

### 실행 후

정산 엑셀을 처음부터 다시 업로드하고, `audit_money.php` 와 `audit_consistency.php` 로 확인하세요.

## render_admin_page.php — 관리자 화면 렌더 점검

관리자 화면을 **실제 라우터로** 열어 보고, 제목·길이와 «조회 폼이 route 를 잃지 않는지» 를 확인한다.
도메인 함수 테스트만으로는 «화면이 열리는지» 를 알 수 없어서 만든 도구다 — 실제로 「광고 클릭 로그」의
조회 버튼이 대시보드로 튕긴 적이 있다(이 관리자는 route 를 쿼리스트링으로 받는데 GET 폼이 그걸 버린다).

### 사용법

```bash
php tools/render_admin_page.php content/ad-clicks
php tools/render_admin_page.php content/ad-clicks from=2026-09-01 to=2026-09-19
```

- 첫 인자는 라우트(`inc/routes.php` 의 키), 그 뒤는 `key=value` 형태의 쿼리 파라미터.
- 로그인은 **본사 최고관리자 세션을 직접 구성**한다 — 비밀번호를 쓰지 않는다.
- 렌더 결과는 `tools/_render_out.html` 로 저장된다(git 에는 올라가지 않는다).

### 읽는 법

```
계정     : admin (org 1)
라우트   : content/ad-clicks
접근권한 : 허용
화면제목 : 광고 클릭 로그
길이     : 44,657 bytes → tools/_render_out.html
GET 폼#1 : route hidden 있음
```

- **접근권한 차단** — 라우트 권한 규칙에 막힌 것이다(`admin_can_access_route`).
- **화면제목이 엉뚱** — 라우트가 안 잡혀 대시보드가 렌더된 것이다. `inc/routes.php` 등록을 확인한다.
- **GET 폼 route hidden 없음** — 조회를 누르면 대시보드로 튕긴다. `<input type="hidden" name="route" ...>` 를 넣는다.

### 언제 쓰나

- 관리자 화면을 **새로 만들거나 고친 직후** — 커밋 전에 한 번.
- 「화면이 안 열린다」·「조회하면 다른 데로 간다」 는 신고를 받았을 때.
